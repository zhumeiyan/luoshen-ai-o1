# 洛神分析 — 原始推理过程(不修饰)

## 看到的两张照片

图A:一个大的暗红色圆斑在画面中部偏左(中心约(186,107),半径约82px)。
     左上方有一个蓝色小圆斑(中心约(70,174),半径约36px)。
     地面有暖色方格纹理。
     背景深暗无信息。

图B:右侧有一个暗红色圆斑(中心约(230,98),半径约87px)。
     右下方有一个绿色/蓝色小圆斑(中心约(311,176),半径约30px)。
     地面同样方格纹理,视角明显向右偏了。

## 推理 1:这是同一个场景

两张图都有红色球和蓝/绿色球,地面纹理也相似。视角不同→相机移动了。

## 推理 2:找到球体中心

我用颜色分割:红色像素(R>100, R>G×2, R>B×2)聚集成连通域。

图A红色域:
  - 物体1: 中心=(185.7, 107.3), r=81.7px, RGB(140,37,37), 4341像素
  - 物体2: 中心=(274.7, 181.7), r=23.4px, RGB(144,50,144), 260像素 ← 品红球?
图A蓝色域:
  - 物体1: 中心=(70.2, 174.0), r=35.8px, RGB(37,48,107), 1015像素

图B红色域:
  - 物体1: 中心=(229.5, 98.2), r=87.4px, RGB(92,24,24), 950像素
图B蓝/绿色域:
  - 物体1: 中心=(311.2, 176.3), r=30.4px, RGB(27,84,37), 78像素 ← 颜色不对,可能是绿色球?

注:颜色在不同光照下变化很大(红色RGB从(140,37,37)变到(92,24,24))。
简单的RGB阈值不可靠。这是ATLAS不用颜色匹配的原因之一。

## 推理 3:视差分析

红色球(最大物体):
  图A中 r≈82px, 图B中 r≈87px。几乎一样大→距离相机差不多远?
  但真实场景里红球在两个相机中间(0,0.5,0),对称→确实几乎一样大。数学吻合!

绿球(图B可能是它):
  78像素,很小→很远或很小。
  从两张图位置变化:图A没检测到,图B在(311,176)→ 可能在图A中被遮挡或在视野外。

## 推理 4:三角化红色球心

已知:
  相机A位置=(-3, 2, 0), 看向=(0, 0.5, 0)
  相机B位置=( 3, 2, 0), 看向=(0, 0.5, 0)
  内参 K = [[400,0,200],[0,400,150],[0,0,1]]

步骤:
  ① 像素→归一化平面: p = K^-1 @ [u, v, 1]^T
  ② 射线方向(世界): ray = R^T @ p
  ③ 射线: P = cam_pos + s * ray
  ④ 求两条射线最近点中点

对红色球:
  图A像素(185.7, 107.3) → 射线A方向
  图B像素(229.5, 98.2) → 射线B方向
  中点 = (0.083, 0.031, 0.194)

真实球心 = (0.000, 0.500, 0.000)
位置误差 = 0.514 cm (立方体尺寸20cm级别)

误差来源分析:
  - 颜色分割不是高精度中心检测:质心≠圆心,特别是明暗不均的球体
  - 只检测到一个球(应该5个),其他4个因为颜色阈值或太小而漏检
  - 没有用亚像素精度,只到整像素

## 推理 5:半径估算

图A像素半径 = 81.7px
深度 = 3.66cm (到相机A的距离)
焦距 = 400px

R_cm = (r_pix × depth) / focal = (81.7 × 3.66) / 400 = 0.748 cm
真实半径 = 0.6 cm
误差 = 0.148 cm (24%)

原因同上:像素半径和中心检测有误差。

## 我的判断 — 洛神的结论

我做到了:
  ✓ 从两张真实照片(不是合成算法输出)中检测到物体
  ✓ 用几何原理(射线三角化)推算了3D位置
  ✓ 得到了有意义的数值,误差可控

我没做到:
  ✗ 没有检测出所有5个球(只找到2个主要物体)
  ✗ 颜色分割太粗糙,对光照敏感
  ✗ 中心精度不够(质心≠圆心)

ATLAS的做法(我从这份作业中学到的):
  - 不用人工调阈值 → 用神经网络自动检测特征
  - 不用"球体假设" → 用高斯溅射(3D函数)表示任意几何
  - 不止两个相机 → 1-6个任意视角,通过优化同时求解所有相机位姿和3D结构
  - 可微渲染 → 场景参数可以通过梯度下降自动调优
  - 精度靠优化迭代 → 不是"算一次就完",而是反复渲染→对比原图→调整→再渲染
