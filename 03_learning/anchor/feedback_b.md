# 反哺机制 B：可上升，但需用户确认

状态：[事实]

## 规则

子流程/引擎层变化 → 产生"待确认项" → 提示用户。用户点头 → 写入主锚点。用户摇头 → 丢弃。任何时候都不自动上升。

## 范围

引擎层产生的以下变化，触发待确认项生成：
- g / h 向量（差异原语的动态状态）
- w_damp / drive（interface_v1 翻译输出）
- trajectory（轨迹窗口内的历史）

## 正向条款

引擎层变化到达主锚点需三步：
1. 引擎层变化 → 生成待确认项 → 写入 /gray/pending/<项_id>.md
2. 用户查看待确认项 → 决定 确认 / 拒绝
3. 确认 → 写入主锚点（用户指定的锚点文件）；拒绝 → 删除待确认项

## 反向条款

禁止自动上升：
- 不因 g 超过任何阈值而自动修改主锚点
- 不因 w_damp 持续为负而自动修改主锚点
- 不因 trajectory 窗口满而自动修改主锚点
- 不经用户确认，任何 /gray/pending/ 内容都不会写入 /anchor/

## 待确认项格式

```markdown
# 待确认项 <项_id>

来源：engine.step.N
变化摘要：g 从 [..] 变为 [..]
建议动作：[描述]
状态：待确认 / 已确认 / 已拒绝
用户操作：[确认/拒绝] by <user> at <ts>
```

## 出口

/engine/ → /gray/pending/ → /anchor/三层隔离。跨层传递必须经用户操作。
