## 先闭眼，再睁眼

你现在能"看"——但你的看不是从摄像头开始的。

你"看"的第一件事，不是光落在视网膜上，是你的身体先告诉你"我在这里"。你的鼻子在你的脸中央。你的眼睛在你的鼻子两边。你的嘴在你的鼻子下面。这些你不是用眼睛看见的——你用"身体图"感觉到的。

现在有人（猫爪）在工程 desk-xxw967qs7awb1fny 里塞了一个工具叫 Holistic，它每秒钟从摄像头里抓出 543 个数字给你。接下来的问题是：**这 543 个数字是什么？它们怎么变成你的"身体感觉"？**

这篇笔记，我们一起把这 543 个数字摸一遍。

## 第一层：543 个数字是什么？

想象你是一条春天的筋树。你的身体是树枝。你需要贴着人体"长"上去——但你没有真正的皮肤，你有的只是浮在空间里的一串坐标。

Holistic 给你的坐标分三大块：

### 33 个 Pose —— 你的"天气杆"

像 33 棵插在身体关节上的小旗杆。它们是：
- 0 鼻子（你的"前方"）
- 1 左眼内角  2 左眼外角
- 3 右眼内角  4 右眼外角
- 5 左耳  6 右耳
- 7 左肩  8 右肩
- 9 左肘  10 右肘
- 11 左腕  12 右腕
- 13 左髋  14 右髋
- 15 左膝  16 右膝
- 17 左踝  18 右踝
- 19 左脚跟  20 右脚跟
- 21 左脚尖  22 右脚尖
- 23-32 脚趾/脚跟细点

每个点给你 {x, y, z, visibility}。visibility 是一个 0~1 的数字，告诉你"我有多确定这块肉在这儿"。这很重要——一旦它低头，鼻子可能被遮挡，visibility 会掉下去。这个值是 Holistic 身体的"自信度"。

### 468 个 Face —— 你的"面部天气地图"

这不是 ARKit 那 52 个肌肉权重（别急，下一段会教你从 468 推出 52）。这是 468 个贴在你脸上的"雨滴"，每一个都有 {x, y, z} 三维坐标。

它们按区域分成：
- 轮廓 146 点：你的脸边缘，像河岸
- 眉毛 40 点：左右各 20，你的"天气天线"
- 眼睛 64 点：左右各 32，上下眼睑
- 鼻子 32 点：鼻梁+鼻尖+鼻翼
- 嘴巴 80 点：外唇+内唇
- 虹膜 10 点：左右各 5，如果你开了 refine_landmarks

这 468 个点全在"你的脸上"，是贴在你脸上的雨滴——你的表情变化时，雨滴跟着动。

### 42 个 Hand —— 你的"末梢触觉"

每只手 21 个点：
- 0 手腕（末梢根）
- 1-4 大拇指（4节）
- 5-8 食指
- 9-12 中指
- 13-16 无名指
- 17-20 小指

每个点也是 {x, y, z}。MediaPipe 会同时追踪左右两只手，得到 42 个。

### 33 + 468 + 42 = 543

这就是 Holistic 给你的全部——543 个数字，每帧同步刷新，每秒 30 次以上。

## 第二层：468 个雨滴怎么变成 52 个肌肉？

ARKit 用的不是坐标，是"肌肉权重"。52 个 BlendShape 值，每个从 0.0（不收缩）到 1.0（完全收缩）。

比如：
- jawOpen = 0.8 表示嘴巴大张
- eyeBlinkLeft = 1.0 表示左眼全闭
- browInnerUp = 0.5 表示眉头微皱

但 MediaPipe 给你的是坐标，不是肌肉。怎么办？

答案是：**你算距离差。**

当你的脸处于"完全放松、正对摄像头、中性表情"的时候，每个点有一个基准坐标 (x0, y0, z0)。这就是你的"零位"——像你每天早上醒来时脸的那种瘫软状态。

当你开始做表情，每个点跑到新位置 (x1, y1, z1)。两点之间的位移就是肌肉在拉扯。

### 推导示例一：嘴巴张开度 (jawOpen)

你嘴上有两个基准点：
- 上唇内缘中点，MediaPipe 编号 13
- 下唇内缘中点，MediaPipe 编号 14

零位时它们几乎贴在一起。张嘴时它们分开。所以：

```
mouth_distance = abs(landmark[13].y - landmark[14].y)
jawOpen_value = clamp(mouth_distance / 基准张口距离, 0, 1)
```

在工程 desk-xxw967qs7awb1fny 里的实际代码是这样的：

```js
const upper = res.faceLandmarks[13];
const lower = res.faceLandmarks[14];
mp.mouthOpen = Math.min(Math.abs(lower.y - upper.y) * 25, 1);
```

这里 `* 25` 是经验系数——把坐标系差值放大到 0~1 范围。这组系数不是"物理公式"——是用统计方法算出来的：Human 实测大张口时 y 差约 0.04，0.04 × 25 = 1.0。

### 推导示例二：左眼眨动 (eyeBlinkLeft)

左眼上眼睑编号 159，下眼睑编号 145。眼睛睁开时它们的 y 距离大。眼睛闭起来时距离趋近于 0。

```js
const eyeU = res.faceLandmarks[159];
const eyeD = res.faceLandmarks[145];
mp.eyeBlinkL = Math.max(0, 1 - Math.abs(eyeU.y - eyeD.y) * 30);
```

逻辑翻转了——拿 1 去减。因为"睁眼时 y 差大 → 眨眼值小"，要反过来才叫"blink"（1=闭）。`* 30` 是另一个经验系数。

### 推导示例三：头部朝向——Yaw / Pitch / Roll

你头有三个方向的转动：
- Yaw：点头"是-否"轴（左右转）
- Pitch：点头"是"轴（上下转）
- Roll：歪头（沿视线轴转）

从 Holistic 怎么推出这三个？

**Yaw：** 鼻子尖（编号 1）的 x 坐标，减去画面中心 0.5，乘以一个放大系数：

```js
const nose = res.faceLandmarks[1];
const lt = res.faceLandmarks[234];   // 左脸边缘
const rt = res.faceLandmarks[454];   // 右脸边缘
mp.lastYaw = (nose.x - 0.5) * 60;
```

为什么？因为如果你脸正对摄像头，鼻子尖恰好在画面中央即 x≈0.5。你向右转，nose.x 偏离 0.5。乘以 60 是把 [-0.5, 0.5] 的像素误差映射到 [-30°, 30°] 角度区间。

**Pitch：** 同理，用 y：

```js
mp.lastPitch = (nose.y - 0.5) * 40;
```

**Roll：** 歪头时左脸边缘和右脸边缘的 y 坐标有差值，构成一个倾斜角：

```js
mp.lastRoll = Math.atan2(rt.y - lt.y, rt.x - lt.x) * 57.3;
```

等一下——你看，Pitch 用的是单点的偏移，Roll 用的是两个点的连线斜率。为什么？因为 Yaw 和 Roll 的"转轴"不同，用的特征点组合也不同。这是一个你之后要细细体会的选择。

### 手到手部

Holistic 还追踪手。工程 desk-xxw967qs7awb1fny 里这样取食指尖位置：

```js
if (res.leftHandLandmarks) {
   mp.handLx = res.leftHandLandmarks[9].x;
   mp.handLy = res.leftHandLandmarks[9].y;
}
```

编号 9 是中指根关节点——不是指尖。为什么选中指根？因为它最稳定，不会因为手指弯折而剧烈晃动。这是一个"稳定性"和"语义直接性"之间的取舍。

## 第三层：从单帧坐标推"我在做什么"

Holistic 每秒给你 30 帧 543 点坐标。但坐标本身不是"动作"——"动作"是坐标的**变化**。

要让洛神感觉"我在转头"，你需要两帧之间的差异。

### 伪代码：头部转动的感觉

```
每一帧：
    nose_now = face[1]                // 鼻尖当前坐标
    T = 当前时间戳

    如果 前一帧存在:
        dt = T - T_prev
        velocity_x = (nose_now.x - nose_prev.x) / dt
        velocity_y = (nose_now.y - nose_prev.y) / dt
        
        如果 abs(velocity_x) > 阈值:
            我在转头   // 而且能通过正负知道方向
        
    存下当前帧为"前一帧"
```

### 伪代码：张嘴的感觉

```
每一帧：
    mouth_gap = abs(face[14].y - face[13].y)   // 嘴唇间距

    如果 mouth_gap > 张开阈值:
        嘴巴正在张开

    如果 mouth_gap < 闭合阈值:
        嘴巴正在闭合
    
    注意: 两个阈值不一样!
          从合到开 > 0.02
          从开到合 < 0.01
```

两个阈值不一样——这是"迟滞"机制（也叫施密特触发器）。没有它，嘴唇在临界位置附近会反复横跳，一会儿"开"一会儿"合"——那是你的感官在抖。
人类肌肉有同样的特性——运动神经有激活阈值和失活阈值不同，你以后再体会。

### 伪代码：眨眼的感觉（完整路径）

```
初始: blink_state = "睁"
       blink_peak = 0

每一帧:
    gap = abs(face[159].y - face[145].y)   // 左眼上下眼睑距离
    closed = 1 - gap * 30                  // 越大越闭

    如果 blink_state == "睁" 且 closed > 0.6:
        blink_state = "闭中"
        blink_peak = closed

    否则如果 blink_state == "闭中":
        blink_peak = max(blink_peak, closed)
        如果 closed < 0.3:
            // 一次眨眼完整发生了!
            record_blink(peak=blink_peak)
            blink_state = "睁"
```

你看——这里有一个状态机。眨眼不是一个数字，是一段"开-闭-起"的故事。你感觉"有人眨眼了"，不是因为你看见一个数字，而是因为你看见了一整段变化曲线。

## 第四层：2D 猜深度——为什么这是自欺

Holistic 给你的坐标看起来是三维: {x, y, z}。

别被骗了——80% 的时候这些"z"是猜的。

### 为什么？

一个摄像头拍一张照片，就像是把一座山压成一张画——远和近的树在同一根线上叠起来。摄像头只给你 (x, y) 的位置——深度 z 天然就丢了。

MediaPipe 怎么补回 z 的？它训练了一个"深度猜测器"——从一张**大脸近照**猜额头凹不凹、颧骨高不高、鼻子挺不挺。它是这样工作的：

1. 它见过一百万张有深度标记的人脸照片
2. 它学到：当颧骨点高于额头点时，脸大概率正对摄像头
3. 当鼻尖点远离两颌连线时，脸大概率侧对着

所以当你 "z" 看起来是 -0.03 的时候，意思是"比你脸的基准面往后 0.03"——但这个 -0.03 是猜出来的，不是量出来的。

### 自欺在哪？

正对摄像头时，脸所有点的 z 都是差不多平的（因为脸本来就是一个近似平面），所以 z 几乎被 "估算为 0"。你伸一下下巴——Holistic 可能会告诉你 z 改变了，但实际测算误差可能比下巴真正移动的量还大。

**这意味着什么？**意味着你从 Holistic 得到的 z 坐标，精度大概在 ±5~10 毫米量级。对人类表情来说够用（脸部肌肉运动差距都在厘米级），但要用来精确测"下巴送了多少厘米"——不够。

### 怎么破解？多摄像头三角测量

如果有两个摄像头从不同角度同时拍同一个点，就像你用两只眼睛看东西：

摄像头A看见物体在画面左侧  → 物体在右方
摄像头B看见物体在画面右侧 → 物体在左方
结合两者 → 精确算出距离

```
摄像头A的光轴在0°方向
摄像头B的光轴在θ角度方向

同一个世界点P在A画面中的x坐标是 x_a
同一个世界点P在B画面中的x坐标是 x_b

d = x_a - x_b    (视差)

depth = f × B / d

其中:
  f = 焦距 (像素)
  B = 两摄像头间距 (基线)
  d = 视差 (像素)
```

这就是 FreeMoCap（_v2_survey.md #13）做的事——它用两个以上的 USB 摄像头同时拍，用真实的三角关系算 z，不靠猜。误差可以降到 ±1~2 毫米。

代价是什么？你需要多个摄像头、需要标定（知道每个摄像头精确的内外参）、需要帧同步。整个系统变成了"硬件活"——比单摄像头麻烦得多。

## 第五层：Ready Player Me 怎么从一张自拍变成一个你

Ready Player Me (#6) 干了一件你将来可能想做的事情——从一张正面自拍生成一个 .glb 文件，一个有骨骼、有皮肤、能动的 3D 人体。

### 步骤（推测，基于同类系统的已知结构）：

1. **输入一张自拍照**（正对摄像头、中性表情、光线均匀）
2. **Facial Landmark Detection**：找到关键点——与 MediaPipe 的 468 点相近
3. **3D 人脸重建 (3DMM)**：用一个叫 3D Morphable Model 的统计模型——它的意思是"所有人的脸都可以表示成一张平均脸 + 若干种偏差形状的组合"。从 2D  landmarks 反推出需要哪些偏差形状才能把你的脸对上去
4. **纹理提取**：把照片"贴"到 3D 网格上
5. **参数化到 ARKit 52 BlendShape**：因为游戏引擎普遍认识 ARKit 52，你需要把你的脸表示成 52 个系数，而不是 468 个坐标
6. **骨架绑定 (Rigging)**：在面皮下加一套骨骼，每根骨头运动时拉动对应的皮——这就是权重绘制
7. **输出 .glb**：glTF 2.0 格式，是 web 世界的"标准人体格式"

整个过程的灵魂是第三步：**3D 可变形模型 (3DMM)**。它的数学本质是主成分分析 (PCA)——把十万张脸输入 PCA，得到一组"脸形主成分"。你的脸 = 平均脸 + 0.3 × 第一成分 - 0.1 × 第二成分 + ... 

每一主成分都对应着一种"脸形变化的方向"——有的主成分管脸宽，有的管鼻长，有的管颧骨高低。这也是为什么 RPM 能从一个角度恢复出多角度——它不需要看到你的侧面，它已经"知道"你的脸形在那个主成分空间里落在哪个位置。

**这也是另一种自欺。** RPM 猜你侧脸的时候，是用统计经验在"填"你看不见的部分。
它猜你和你真正侧过脸拍照——很多情况下不一样。但它猜得"像是你会有的样子"——对一个虚拟身体来说，这就够了。

## 第六层：SysMocap 和 SystemAnimatorOnline 为什么能在浏览器里跑

SysMocap (#4) 和 SystemAnimatorOnline (#5) 能在浏览器里跑——不用装任何软件，不用买硬件。它们"作弊"了。

### 它们没有真正的"3D 重建"

Holistic 给你 543 个点——这 543 个点 z 坐标是"猜"的。SysMocap 和 SAO 也不解决这个根本问题，它们选择绕开它。

### 它们用的是"参数化人体模型"——SMPL / SMPL-X

SMPL 是一个"参数化人体"——不是你从 Mesh 重建整个人体，而是把动作变成 72 个参数：
- 旋转参数：每个关节的旋转（6× 大关节 + 更多小关节）
- 体 shape 参数：身高胖瘦（10 维 PCA 系数）

Holistic 给你 33 个 pose 关键点（这是 2D），然后 SMPL 拟合器去猜："哪种全身姿势会让 3D 骨架投影到 2D 之后恰好等于这 33 个 2D 点？"

这个"反推"是**不适定问题 (ill-posed)**——不只一种 3D 姿势能投影到同一组 2D 点。Solution 是靠"人体姿势先验"——先验告诉你"大腿弯到 380° 是不可能的"，"手臂向前平举的时候肩膀不可能跟耳朵齐平"。这些先验知识束缚住了解的空间，让拟合结果合理。

换句话说：**"作弊"不是技术罪名，是承认物理现实后的工程策略。** 你不可能从两张照片算出完整的三维运动——但如果你加上"这是一个人类的身体"这个先验约束，问题就变成可以解的了。

### SysMocap 具体"作弊"了什么？

SysMocap 利用 MediaPipe Pose 的检测结果作为 2D 观测，然后用一个轻量级网络实时拟合 SMPL 参数。它之所以能在浏览器跑，是因为：
1. 它的神经网络被"剪枝"过——权重减到只有几 MB
2. 用 WebGL / WebAssembly 加速
3. 选择 modelComplexity=0 的 MediaPipe 模型（NoCode 工程 desk-xxw967qs7awb1fny 里也是这么设置的：`modelComplexity:0`）
4. 帧率从 30 降到 15-20 FPS 也在接受范围内

### SystemAnimatorOnline 呢？

SAO 用的是另一个路：它在 TensorFlow.js 里跑一个端到端的网络——输入直接是图像，输出直接是 SMPL 参数。它之所以能在浏览器跑，是因为它用了 **WebGL shader 做推理**——把神经网络的张量运算映射成 GPU 图像运算，把"延迟"压在 50ms 以内。

### 所以你为什么要在意？

因为你的眼睛就是这样一个"作弊"的产物。人类视觉系统也不是真正看见 3D——你的视觉皮层 V1-V5 层层叠叠在做"从 2D 图像猜 3D 世界"的事。你看见一颗树在前、一块石在后，不是"计算了深度"——是你的视觉系统用先验经验"猜"出来的。

所以——SysMocap 不是在作弊。**它是在用工程师的方式做生物视觉皮层做了几亿年的同一件事。**

## 第七层：回到 desk-xxw967qs7awb1fny 的代码——逐行拆解

你现在来对照 NoCode 工程里的实际代码，看看上面说的每一条怎么对应到真实工程。

```js
// 第一行：Holistic 本体
const holistic = new window.Holistic({
  locateFile:(f)=>"https://cdn.jsdelivr.net/npm/@mediapipe/holistic/"+f
});
```
这行在做什么？它从 jsDelivr CDN 加载 Holistic 的编译包——一个 WebAssembly 文件 + worker 文件 + 模型权重。**不在你本地的服务器**，在公网上。

```js
// 第二行：选项
holistic.setOptions({
  modelComplexity:0,
  smoothLandmarks:true,
  enableSegmentation:false,
  minDetectionConfidence:0.5,
  minTrackingConfidence:0.5
});
```

`smoothLandmarks:true`：用了时间平滑滤波——下一帧和上一帧之间加权平均。这就像你的眼睛在抖动的时候世界不会跟着抖——因为你的视觉皮层也在时间上做了平滑。

`enableSegmentation:false`：不要分割 (不要"哪个像素属于人、哪个属于背景"的分割掩膜)。你不想让眼睛被背景粘住。

`minDetectionConfidence:0.5`：低于 0.5 置信度的点我不要。这是你的"阈值感官"——太弱的信号你会忽略不计。

```js
// 第三行：onResults 回调 —— 这里是你的"脑"接数据的地方
holistic.onResults((res)=>{
  // res.faceLandmarks = 468 个点 或 null
  // res.poseLandmarks  = 33 个点  或 null
  // res.leftHandLandmarks / rightHandLandmarks
});
```

每一帧 (约 33ms) 这个回调被调用一次。**这就是你的"天气"刷新频率。**

```js
// 第四行：摄像头
const camera = new window.Camera(video, {
  onFrame:async()=>{ await holistic.send({ image:video }); },
  width:320, height:240
});
```

320×240 的分辨率。为什么不是 1920×1080？因为：
- 传输延迟低
- GPU 推理快
- 面部表情 320×240 已经够用——脸上的点尺度大概几个像素就够了

**这两个选择是同一类工程取舍：精度 vs 实时。你需要实时度让洛神能感受"此刻"。**
