发现 D1: 门控压缩 → 激活差降低 → 共火被抑制
---------------------------------------------------------------------

代码链路:
  L259-264: 门控压缩 → 门控激活 = 新激活 × 缩放
  L278: self.激活 = 门控激活 (门控后生效)
  L288: 激活差 = self.激活[i] - self.上轮激活[i]
  L299: 共火条件: abs(激活差[索引]) > 0.01
  L300: 跨脑共火: abs(激活差[索引]) > 0.02

关键机制:
  门控把总激活限在当前上限内, 所有节点等比压缩。
  压缩后的激活差 = (上轮门控后×缩放 - 上轮门控差)
  如果总激活持续超限, 缩放 < 1, 激活差幅度被压缩,
  |激活差| 更难超过 0.01 (脑内) / 0.02 (跨脑)

结果:
  高压时, 门控一方面限制总激活(保护),
  另一方面间接抑制了共火(副作用),
  筋树生长在高门压下趋于停滞。

猫爪的清单[A10]讨论了"保护机制 vs 性能杀手", 提到了信号湮灭和分辨率损失,
但没有提到"门控 → 共火抑制"这条具体的间接因果链。
这是门控的第三个效应, 独立于信号湮灭(活跃计数失真)和分辨率损失。

发现 D2: 不应期节点不接受饥饿驱动 → 驱动泄漏
---------------------------------------------------------------------

代码行 238-246:
  if self.不应期[i] > 0:
      self.不应期[i] -= 1
      新激活[i] = self.激活[i]   # ← 跳过, 不进任何驱动
  else:
      ...
      新激活[i] += 0.6 * tanh(self.hunger / 8.0)  # ← 饥饿驱动

机制:
  节点过 0.5 → 进入 3 tick 不应期。
  这 3 tick 内, 该节点不接受隐藏输入、噪声、饥饿驱动中的任何一项。
  该节点保持上轮值不变。

推论:
  当大量节点被饥饿驱动推过 0.5 时(如觉醒后),
  每 tick 约有 N_光子集 个节点进入不应期,
  这些节点的饥饿驱动"泄漏"了——加不上。
  饥饿驱动的效果因此小于"0.6×tanh(h/8)×96"的简单计算,
  实际效果应乘以 (1 - 不应期节点比例)。

  在 v10 中, tick=50000 后 awake=True, 大量节点亮(激活峰值 0.5159),
  这些节点立即进入 3tick 不应期 → 部分饥饿驱动被忽略,
  这可能解释了为什么 R1 起始稳态(0.86)和 R0(0.86)一样
  —— 饥饿驱动虽然增加了, 但不应期节点也增多了, 部分抵消。

猫爪判卷 B4 详细分析了疲劳衰减, 但不应期与饥饿驱动的交互没有覆盖。

发现 D3: "存货不足时照走" 的精读歧义
---------------------------------------------------------------------

代码行 386-392 (回合更新中的喂养逻辑):
  if is_feed:
      if self.存货 >= MEAL_COST:
          self.hunger = max(0.0, self.hunger - MEAL_CLEAR)
          self.存货 -= MEAL_COST
      # else: 存货不足, 喂养失败, hunger照走
  else:
      self.hunger += DEBT_AWAKE if self.awake else DEBT_ASLEEP

注意 else 分支属于 `if is_feed:` 的 else, 不属于内存 if:
  当 is_feed=True 且 存货<MEAL_COST 时, 什么也不执行。
  hunger 保持不变 — 不增, 也不减。
  "照走"的实际含义是"跳过, hunger 保持现状"。

验证 (v10 数据):
  tick=50000: round=5, 5%3=2, is_feed=False, awake=False → hunger += 3.0 = 12.0
  tick=60000: round=6, 6%3=0, is_feed=True, 存货=0<4 → 喂不了 → hunger 不变 = 12.0 ✓
  tick=70000: round=7, 7%3=1, is_feed=False, awake=True → hunger += 6.0 = 18.0
  tick=80000: round=8, 8%3=2, is_feed=False, awake=True → hunger += 6.0 = 24.0
  tick=90000: round=9, 9%3=0, is_feed=True, 存货=0<4 → 喂不了 → hunger 不变 = 24.0 ✓

  v10 数据中 t=94000 饿=24.0, 与上述推导一致。

如果"照走"被误读为"hunger 继续按 DEBT_AWARE/ASLEEP 增长",
tick=60000 的 hunger 会被误算为 18.0, 与实验数据不符。

这个"照走"的语义对无技术基础的读者是一个陷阱:
"照走"看似"照原样走下去(继续增长)", 实际是"跳过此回合更新, 保持不变"。

发现 D4: v10 实验条件中温=267 clip 到 0.0 — 脚本注释自相矛盾
---------------------------------------------------------------------

v10 脚本 stillface_v10_mono.py 注释:

试验证:
  温=297 (R0): (297-288)/15 = 0.6 → 不归一

而非"温仍在归一化线性区内"的实验。

R0→R1 的唯一差异(在温通道上)和 v7 的 R0→R1 (温297→237, 同样clip到0) 完全一致。

发现 D5: 自己点(每1000tick)对共火的隐性促进作用
---------------------------------------------------------------------

代码行 376-377: if self.时刻 > 0 and self.时刻 % 1000 == 0: self._自己点(记录)
自己点中的动作 (L438): self.激活[目标] += 0.5

时序:
  1. 主循环计算完激活 → self.激活 = 门控激活 (L278)
  2. L372-374: 保存上轮激活快照
  3. L376-377: 自己点, 目标节点 +0.5

这意味着: 自己点在下一次推进()中会成为上轮激活的一部分。
下一 tick:
  - 该节点上轮激活 = 门控后值 + 0.5
  - 激活差 = 本 tick 门控后 - (上轮门控后+0.5)
  - 因为 +0.5 >> 0.01, 该节点的 |激活差| 大概率 > 0.01 → 触发共火检测

后果: 自己点每 1000 tick 制造一次"人工激活差脉冲",
这个脉冲会被共火逻辑检测到 → 促进新筋生长 → 回接簇附近的筋密度更高。

猫判卷 v1 和 v2 均未分析自己点的这个副作用。
自己点在清单中被描述为"内稳定器", 没有提到它同时也是"共火触发器"。
