## 模块 A:门控缩放(Engine Clamp)

### A1. 上限满值 = 6.0 在哪里?做什么用?

**代码位置**:
- L49:形参 `上限满值=6.0`
- L107:`self.上限满值 = 上限满值`
- L274:`目标上限 = max(0.01, self.上限满值 * (1.0 - 压力))`

**作用**:门控系统的理论天花板。当前上限在历史值和目标上限之间做指数滑动平均(L275:0.9×历史 + 0.1×目标),而目标上限 = 上限满值 × (1 - 压力)。

上限满值 = 6.0 意味着:**零压力时**,系统允许全部节点的总激活(|激活₁| + |激活₂| + ... + |激活₉₆|)最多到 6.0。

换算:如果全部 96 节点均匀分担,每个节点均摊 6.0/96 = 0.0625。远低于活跃阈值 0.1。也就是说——满值 6.0 对应的"全脑均匀点亮"状态,几乎所有节点都**低于**活跃计数(见 A8)。

### A2. 温度满值 = 1.5 在哪里?为什么用它做除数?

**代码位置**:
- L49:形参 `温度满值=1.5`
- L109:`self.温度满值 = 温度满值`
- L271:`温度饱和度 = 热量 / self.温度满值`

**热量计算**(L268):`sum(值 * 值 for 值 in 门控激活)` = L2 范数平方。

为什么用 1.5 作除数?——1.5 是"热量多少算满"的参考点。

**数字推演**:
假设 N 个节点同时以幅度 a 激活:热量 = N × a²。
- N=30, a=0.2:热量 = 30 × 0.04 = 1.2 → 饱和度 0.80
- N=15, a=0.3:热量 = 15 × 0.09 = 1.35 → 饱和度 0.90
- N=10, a=0.387:热量 = 10 × 0.15 ≈ 1.5 → 饱和度 1.0

所以 1.5 对应的是"中等数量的节点以中等幅度持续激活"场景下的热载荷,不是极端满载。

### A5. 压力 = max(...) 而不是 sum(...),意味着什么?

取 max 意味着:**压力由最紧张的那个维度决定,三个维度互相竞争但只取最大**。

与 sum 对比:
- sum:多个维度略高就叠加 → 更快触达 1.0 → 过度降压
- max:只按最狠的那个 → 其它维度还有呼吸空间

**例**:假设内存=0.2,温度=0.3,功耗=0.1。
- max:压力=0.3,目标上限=6.0×0.7=4.2
- sum:压力=0.6,目标上限=6.0×0.4=2.4

max 让系统**在单维度紧张时仍保持较高上限**,不会过度震抑。

### A6. 压力=1.0 时上限多少?压力能到 1.0 吗?

目标上限 = 6.0 × (1.0 - 1.0) = 0.0。
但 L274 clamp:`max(0.01, ...)` → 目标下限 = 0.01。

**压力=1.0 是否可能?**看三个饱和度能否到 1.0:
- 温度饱和度=1.0:热量=1.5 → **可达**(例:15 节点×0.316²≈1.5)
- 功耗饱和度=1.0:活跃节点数=15 → **可达**(只要 15 个节点>0.1)
- 内存饱和度=1.0:筋树数=9120 → **名义可达,实际极难**(见 B7)

所以**压力=1.0 完全可能**(温度或功耗先到 1.0),但此时目标下限 clamp 到 0.01,系统进入深度限流。

### A7. 当前上限 ← 0.9×旧 + 0.1×目标。特征时间多少 tick?

**指数滑动平均(EMA)**:
- 系数 a=0.9
- 半衰期:t_{1/2} = ln(2) / (-ln(0.9)) = 0.6931 / 0.10536 ≈ **6.58 tick**
- 2/3 响应:1 - 0.9^t = 2/3 → 0.9^t = 1/3 → t = ln(1/3)/ln(0.9) ≈ **10.4 tick**

约 10 tick 走 2/3 的距离。心跳周期也是 10 tick(L18)。**门控响应速度 ≈ 一个心跳周期**——相对慢的自动增益控制。

注意:因 max(0.01,...) 的 clamp,当前上限不会低于 0.01。

### A8. 等比压缩:**每个节点除以同一个系数**——影响相对差异吗?

**数学**:
原节点 A=a,节点 B=b,压缩系数 s(0<s<1)。
压缩后 A'=a×s, B'=b×s。比值 A/B = a/b = A'/B'——**比值不变,相对差异保留**。

**但活跃计数巨变**:
活跃阈值 |激活| > 0.1(用于 L269 功耗饱和度)。
压缩后所有节点等比缩小——**原本略高于 0.1 的节点会掉到 0.1 以下,不再计入活跃**。

**具体场景**(信号湮灭效应):
假设 96 个节点全部以 0.3 激活。
总激活 = 96×0.3 = 28.8。
如果当前上限=6.0,压缩系数 s = 6.0/28.8 ≈ 0.208。
压缩后所有节点 = 0.3×0.208 = 0.0625 < 0.1 → **活跃节点数 = 0**。

一个"全脑均匀活跃"状态经过门控,变成**全部静默**状态——功耗饱和度立刻归零,但温度饱和度(热量 = 96×0.0625² = 0.375)不为零。
**这是信号湮灭,不是保护**。

### A10. 门控缩放是"保护机制"还是"性能杀手"?——用数字论证

**保护证据(防爆炸)**:
无门控时,X(t+1) = X(t) + 0.1×隐藏输入。若隐藏输入持续为 0.5(保守值),激活线性增长:tick=10 时 ≈ 5.0,tick=20 时 ≈ 10.0 → 数值爆炸。门控将其限在总激活=6.0 以内。

**性能杀手证据(信号湮灭,见 A8)**:
全脑 0.3 激活 → 压缩系数 0.208 → 全脑 0.0625 → 全部低于活跃阈值 0.1。
一个"所有节点都参与但幅度温和"的状态,经过门控,**等于"什么都不做"的状态**——功耗饱和度 0,总激活压缩到 0.0625×96=6.0。

**另一个数字论证——分辨率损失**:
假设两个节点的真实信号分别是 0.2(弱)和 0.4(强),压缩系数 0.5。
压缩后:0.1 和 0.2——比值保留 2:1。
但从活跃计数看:只有 0.2 被计入(>0.1),0.1 被丢弃。原始"强节点是弱节点的 2 倍"信息仍然存在,但**弱节点被隐藏**。

再来一重压缩(假设压力继续高):0.2 再压缩 0.5 → 0.1,**等于门槛**。任何一丁点波动就让节点在"活跃/不活跃"之间跳变。

**数字结论**:
- 保护:模拟积分器不发散,数值稳定。
- 代价:信号被压到活跃阈值附近,分辨率损失大(尤其当上限<3 时)。
- 偏**不是二选一,而是权衡**:短期保护(防爆炸) vs 长期失真(湮灭温和信号)。

### B6. 筋被剪后,原来经过它的信号会去哪?

**代码位置**:
- L358-359:`del self.筋树[筋键]` + L360 `self._缓存有效 = False`
- 下次推进调用 L217 `_同步数组` 重建 `_筋键列表`,不再包含此筋
- L339 的循环不再包含此筋

**直接结论**:信号通路断了,**没有绕路或替代路径**。完全中断。

**但有延迟缓冲残留**:
- L34 `_传导加速` 里的延迟缓冲长度 1-5
- 被剪筋在延迟缓冲里还存着最近 1-5 tick 的信号
- `_写回延迟缓冲`(L148-157)会把残留的移回字典,但字典已经 `del` 掉了,写回找不到
- 所以:**残留信号也无法输出到任何节点**

**例外**:如果筋被剪的时刻,有某条信号刚刚进入延迟缓冲的"端口位置"(d=0),那条信号会在筋被剪后的**同一 tick** 输出到目标节点(L29 读 `延迟缓冲[d,0]`)。但之后 1-5 tick 内延迟缓冲剩下的旧信号条目会被移位到 d=0 位置,再运行传导循环时这些条目会被读出并累加隐藏输入(L39 `隐藏输入[i] += 到达信号`)——但此时筋已经不在循环里,**读不到**。

所以 **残留信号不会逃逸**。信号完全中断,无任何绕路。

### B7. 筋数上限分析:真能到 9120 吗?

### B8. 筋树对"学习"有用吗?

**场景**:反复接受同一温/力输入。

**推演**:
1. 反复同一输入 → 感受器驱动同一组节点反复出现激活差
2. 如果同一对节点每 tick 都出现 |差|>0.01(L299),它们满足共火条件
3. 概率 0.15(L324)建新筋,或走 L330-333 增强已有筋(位点+1)
4. 多次反复 → 某些筋位点从 1 长到 40 上限

**"学了什么"**:不是输入的具体数值,而是**"哪些节点倾向于一起激活"的结构模式**。

**有益方面**:
- 固定路径后,信号传导效率提高(位点 1→40,传导信号 40 倍)
- 降低未来达到同样激活所需的感受器驱动

**有害方面**:
- 如果输入变化了,老筋还在传导(且位点巨大的旧筋占主导)
- **没有"老筋因信号不同而减弱"的机制**——位点只增不减直到废退(5000 tick 延迟)
- 反复的旧模式可能掩盖新模式信号

**结论**:筋树是一种**慢时的结构学习**,记忆"谁和谁一起动",不记忆"动了多少"。有益(模式固定时高效)+ 有害(模式变化时惯性干扰)。

### B9. 脑内共火概率 0.15 → 0.5,行为有何变化?

**直接变化**:同脑内连筋概率提升 3.33 倍。

**数字推演**:
假设某稳态下每脑 5 个节点亮,无序对 C(5,2)=10,有序对 20。
- 原:20 × 0.15 = 3 新筋/tick/脑,4 脑 = 12 根/tick 新筋上限
- 改后:20 × 0.5 = 10 根/tick/脑,4 脑 = 40 根/tick

增速 3.33 倍 → 筋数增长加速 → 内存饱和度上升加速 → 门控上限下降加速。

**非线性反馈**:
- 更多筋 → 更多传导路径 → 更多激活累积
- 门控上限等比压缩(0.9/0.1 EMA,≈10 tick 响应)
- 压缩后激活降低 → 下 tick 激活差降低 → 共火条件更难满足(L299 |差|>0.01)
- 负反馈抑制进一步连筋

**净效应**:概率 0.5 会短期提升连筋速度,但更快触发门控压缩,最终筋数平衡点更高但**不是 3.33 倍**(因为门控反压),可能是 1.5~2 倍。具体数字需跑台,这里是手算推演。

### B10. 筋树和门控缩放有没有负反馈回路?

**引导里的回路假设**:
有筋树 → 传导激活 → 热量上升 → 温度饱和度上升 → 门控上限下降 → 被压制的激活更少传导 → 筋树位点下降 → 筋数减少

**逐步验证**:

1. 有筋树 → 传导激活 ✓(L32 信号 = 位点×疲劳×激活×差因子)
2. 传导激活 → 热量上升 ✓(L268 热量 = 门控激活²)
3. 热量上升 → 温度饱和度上升 ✓(L271)
4. 温度饱和度上升 → 门控上限下降 ✓(L273 压力 max; L274 目标上限 = 6.0×(1-压力); L275 EMA)
5. 门控上限下降 → 等比压缩 ✓(L259-261)
6. 压缩后激活降低 → 下 tick 激活差降低 ✓(压缩后所有节点等比下降)
7. 激活差降低 → 共火条件更难满足 ✓(L299 |差|>0.01 门槛)
8. 共火减少 → 筋末传不再更新 ✓(L331 末传=self.时刻 只在共火时更新)
9. 末传停止更新 + 5000 tick 延迟 → 废退触发 ✓(L350)
10. 废退到 0 → 筋被剪 ✓(L353)
11. 筋被剪 → 内存饱和度下降 ✓(L272 = len/9120)
12. 内存饱和度下降 → 门控上限回升 ✓(L274 目标上限)

**结论:回路存在**。

**但它是负反馈稳定器吗?**——部分是:

- **短期(1-5000 tick)**:回路 1-7 即时生效(压缩抑制激活 → 抑制共火),但筋树拓扑变化需要 >5000 tick 才通过废退反馈。
- **长期(>5000 tick)**:废退 → 筋剪 → 内存饱和度降 → 门控上限回弹 → 激活不再被压 → 可能共火增加

**时滞不匹配**:
- 门控:10 tick 响应(快)
- 废退:5000-8000 tick(慢)

**短期可能振荡**:
筋树扩张 → 门控限流 → 但限流只压制"激活幅度",不直接剪筋 → 筋继续存在、位点继续增长(共火时如果 |差|>0.01 仍会增强 L332-333) → 直到某条筋的末传真的 5000 tick 没更新才废退

**短期看,门控缩放主要是"压缩信号"而非"删除筋"**。筋树增长受限于共火条件 |差|>0.01,这由输入信号决定、不直接被门控影响。所以门控缩放像一个**慢增益控制**,不是快反馈回路。

**最终判定**:回路存在,但**不是纯粹负反馈稳定器**,因为时滞大(5000+ tick),筋树结构惯性,以及"共火条件需要 |差|>0.01,与门控无关"。更像是一个**慢节奏耦合的双系统**。

## 新发现(清单未覆盖)

### 发现 1:筋疲劳衰减机制与引导假设根本不符

引导假设"每 200 tick,50% 概率 × 0.9"——代码实际:
1. **所有筋每 tick 都衰减**(L342,循环遍历所有筋键,L339 用 L228 `list(self._筋键列表)` 取全部)
2. 下限 0.2 截断
3. 每 100 tick 有恢复公式(L356 `筋 += (1/3)*(1-筋)`)
4. L346-347 的"200 检查"里是 `pass`,什么都没做(被禁用)

这意味着代码行为与设计意图(如果引导是意图的话)完全不同——是设计失误还是有意为之?不确定。但代码就是如此,不能按引导假设回答。

### 发现 2:门控压缩导致"活跃计数失真"

L259 门控触发:|总激活| > 当前上限。
压缩系数应用于所有节点。
L269 活跃计数:|门控激活| > 0.1。

如果压缩前所有节点平均 0.3 激活,压缩系数 0.208,压到 0.0625——活跃计数=0。

**门控压缩让"活跃节点数"这个指标失去区分度**:
- 压缩前:96 个活跃节点
- 压缩后:0 个活跃节点
- 但实际激活能量(热量)仍然存在(虽然也被压缩)

功耗饱和度(L270)和温度饱和度(L271)在此场景下给出矛盾读数:
- 功耗饱和度 = 0(没有活跃节点)
- 温度饱和度 = 0.375/1.5 = 0.25(仍有一些能量)

取 max(L273)后压力由温度决定,但**功耗饱和度的"0"掩盖了"其实还有大量节点参与"的事实**。这是"阈值后的绝对值信息被丢失"的一个例证。

### 发现 3:废退时序精确定位——首次废退在 +6000,不是 +5000

L350:`if self.时刻 - 筋['末传'] > 5000 and ... % 1000 == 0`
- `>` 5000 排除 5000(如果 末传=0,tick=5000 时:-5000=5000,5000>5000 为假)
- `% 1000` 只允许 6000,7000,8000,...
- 所以首剪在 末传+6000,如果初位点=1

同为"边界精度"问题,类似上次发现的"哭第 5 轮还是第 4 轮"。代码里的 `>` and `%` 联立不是简单线性翻译。
