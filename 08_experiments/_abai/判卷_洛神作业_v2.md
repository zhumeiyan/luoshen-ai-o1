### B4:疲劳衰减机制

**判题:洛神对。我的讲课稿前提"每 200 tick,50% 概率 × 0.9"是错的。**

代码逐行核对:

```python
L339:  for (j, i) in 传导过:                    # 遍历所有筋键
L340:      if (j, i) in self.筋树:
L341:          筋 = self.筋树[(j, i)]
L342:          筋['疲劳'] = max(0.2, 筋['疲劳'] * 0.9)   # ← 每 tick × 0.9
L346:          if 筋['传导次数'] % 200 == 0 and random() < 0.5:
L347:              pass                                 # ← 什么都没做
L356-357:  if self.时刻 % 100 == 0:                     # ← 每 100 tick
               筋['疲劳'] += (1/3) × (1 - 筋['疲劳'])   # ← 恢复
```

洛神的解读:
- "所有筋每 tick 都衰减" — 代码 L339+L342 确认 ✓
- "约 16 tick 就降到下限 0.2" — 0.9^n = 0.2 → n = ln0.2/ln0.9 ≈ 15.3 → 约 16 tick ✓
- "每 100 tick 有恢复" — 代码 L354-357 确认 ✓
- "L346-347 的 200 检查是一个被禁用的代码(pass)" — 注释也说了"延迟不再衰减,保持随机分布" ✓

**稳态振荡计算:**
- 100 tick 周期:每 tick ×0.9,约 16 tick 降到 0.2,然后 84 tick 在 0.2 下限
- 每 100 tick 恢复:0.2 → 0.2+0.8/3 = 0.467
- 平均疲劳 ≈ 0.213

以上推导数学自洽。

**修正我的认知:** 原来我以为的"每 200 tick 50% 概率"可能是对 L346 的误读。代码实际 L347 是 `pass`,每 200 tick 的衰减事件从未发生过;而真正的衰减是每 tick L342。这要么是代码写坏了,要么是设计者有意让 200 tick 衰减无效。无论代码意图是什么,当前代码行为 = 洛神说的。

### B5:静默 → 筋被剪的 tick 数

**判题:洛神对。边界精确性再次抓到。**

代码证据 L350:
```python
if self.时刻 - 筋['末传'] > 5000 and (self.时刻 - 筋['末传']) % 1000 == 0:
```

边界分析:
- `>` 5000 排斥 5000 本身
- `% 1000 == 0` 在差值∈{1000,2000,...,5000,6000,...}中筛选
- 第一个同时满足两者的数:6000

若初位点=1,末传=0:
- tick=5000: 5000 > 5000 假 → 不剪
- tick=6000: 6000 > 5000 真 AND 6000 % 1000 == 0 真 → 触发 → 位点 1-1=0 → 0<1 → 死
- **需 6000 tick。**

若初位点=3:
- tick=6000:位点=2; tick=7000:位点=1; tick=8000:位点=0 → 死
- **需 8000 tick。**

洛神两个选项都列出了。代码对照确认无误。

**注释:这是继 v1 的"哭检查时序"之后,洛神第二次在边界条件(`>`/`≥` + 联合判据)中找到精确行为。这种对"非线性边界组合"的警觉性,是洛神实际建立起来的认知能力之一。**
