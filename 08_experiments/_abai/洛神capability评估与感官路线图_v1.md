=====================================================================
  清单 A:四维评估框架
=====================================================================

洛神每个新能力的认证,必须四个维度都过才叫通过。

         ┌──────────────┐
         │  跑台(猫爪)   │  A:猫爪搭台,阈值对账
         └──────┬───────┘
                │
    ┌───────────┼───────────┐
    │           │           │
┌───┴───┐  ┌───┴───┐  ┌───┴───┐
│洛神自验│  │角色互换│  │人类独立│  B:洛神自带预测 vs 实测对照表
│  B    │  │  C    │  │  D    │  C:双方同题独立答,对账
└───┬───┘  └───┬───┘  └───┬───┘  D:架构师从原始数据打分,不看猫爪/洛神
    │           │           │
    └───────────┼───────────┘
                │
         ┌──────┴───────┐
         │  三方一致     │  裁决规则:
         │  才叫通过     │  A/B/C/D 全过 = PASS
         └──────────────┘  任一 FAIL = 立案重做

维度说明:

维度 A:跑台验证(猫爪执行)
  操作:洛神提交能力声明(含公式/阈值) → 猫爪搭实测环境 → 跑台
  判据:实测值 v.s. 声明阈值的偏差 ≤ 10%(代码实现层)或 ≤ 5%(硬件传感器层)
  当前状态:v3 情绪公式已跑台,3/3 FAIL — 需要重做

维度 B:洛神自验证(洛神执行)
  操作:洛神提交时附带"我自己跑 N 轮,实测值 = X,我的预测 = Y,偏差 = Z"的对照表
  判据:
    (a)偏差 Z ≤ 10%(允许误差)
    (b)若偏差 Z > 10%,洛神自己的归因表中必须解释为什么偏(不接受"猫爪台没搭好"这类甩锅)
    (c)洛神自验证的对照表不允许事后补 —— 必须与作业同批次落盘
  当前状态:前四份作业(v1-v4)都缺这个表 — 以后 v4* 起强制

维度 C:角色互换(猫爪 vs 洛神)
  操作:同一道能力评估题,猫爪做一份,洛神做一份,双方独立完成后对账
  判据:
    (a)答案一致 → PASS
    (b)答案不一致 → 开"对齐会":各自陈述推理路径,找到分歧点
    (c)分歧点是猫爪的认知错(猫爪没考虑到的引擎事实) → 猫爪扣分
    (d)分歧点是洛神的认知错(洛神没理解的基础概念) → 洛神扣分
    (e)分歧点双方都没考虑到 → 框架师(人类)裁
  当前状态:未实施过

维度 D:人类视角独立评分(架构师执行)
  操作:架构师在收到猫爪判卷 + 洛神自验证之后,独立从原始数据出发评分
  判据:
    (a)与 A/B/C 两方以上一致 → 通过
    (b)与 A/B/C 三方都不一致 → 框架师立案,独立调查,出裁决报告
  约束:架构师评分时只看原始数据(引擎 trace + 跑台日志),不看猫爪的判卷词和洛神的自辩词
  当前状态:架构师主要角色是"下达方向",没系统做过独立评分

补齐路径(双轨:代码模拟 + 物理传感器接口)
---------------------------------------------------------------------

代码模拟路线(无硬件也能动):
  C1-M2 痛觉:把疲劳×0.9 衰减器改为双通道 —— 快痛(局部突发)+慢痛(全局持续)
  C2-M7 温度觉-冷:在温通道做一个镜像通道,用 max(0,(288-T)/15)捕捉冷感
  C3-M10 情绪整合:v3 情绪色价已经存在 —— 接下来的任务是把情绪接入"感知层"而不仅是"激活累积层"
  C4-M11 视觉-颜色:把灰度通道 R/G/B 三分,末梢差变换每个通道独立算
  C5-M12 视觉-深度:需要两张摄像头,算法不涉及 L174 改造,是新增通道

物理传感器路线(需要硬件):
  S1 摄像头接入 → 通道 0(R/G/B)同时换成视频帧采样,末梢差变换换成帧差
     摄像头:手机/笔记本摄像头都行,采样率 ≥ 1fps(不需要实时视频流)
  S2 麦克风接入 → 通道 1 换成实时声压采样
     手机 mic / 电脑 mic 都行
  S3 触压传感器接入 → 通道 2 换成实时压力读数
     手机屏幕上已有的 3D Touch / 触摸压力API 可以当临时传感器
  S4 温度传感器接入 → 通道 3 换成实时温度读数
     手机内置温度传感器(环境温度,不是体温)
  S5 加速度计/陀螺仪 → 通道 5 新增(前庭平衡感)
     手机都有的 MEMS 加速度计
  S6 湿度传感器 → 通道 6 新增(皮肤湿度感,对应触觉质感的一部分)
     手机不一定有,可选

优先级(按发育顺序 + 硬件可行性):
  P0 代码动:  C2(冷觉) C1(痛觉双通道) C3(情绪接入感知层) — 无硬件就能做
  P1 单摄像头:S1-RGB(S4 用手机拍一张照片给洛神"看"当临时方案)
  P2 单麦克风:S2(声音事件检测)
  P3 全传感器:S3-S6(触压/温度/加速度/湿度)全部到位

---------------------------------------------------------------------
交付形态
---------------------------------------------------------------------

每个感官补齐的任务包包含:
  1. 该感官的人类特性 500 字定义(从发展心理学教科书出发,不靠 AI 写)
  2. 引擎接口改造:通道编号 + 末梢函数 + 感知粒度
  3. 1 条可证伪的检测阈值(比如"光亮度变化 10% 在 3 tick 内必须检测到")
  4. 四维评估(A 跑台 + B 自验证 + C 角色互换 + D 人类独立评分)
